# SECURITY_BACKLOG.md — ranked, with the exact fix

Severity: **P0** = ship-blocker / money or account loss. **P1** = exploitable but bounded.
**P2** = hardening. Each item is one PR. Do them in order.

## P0 — do not launch without these

| ID | Issue | Where | Fix |
| --- | --- | --- | --- |
| S-01 | **CSRF wide open.** Cookies are `SameSite=None; Secure` with no CSRF token. Every POST/PUT/DELETE is forgeable from any origin. | `deps.py:91-95` | Add double-submit: on login set a non-httpOnly `csrf_token` cookie + return it; require header `X-CSRF-Token` to match on every non-GET. Enforce in one FastAPI middleware, not per-route. Also add strict `Origin`/`Referer` allowlist check. Move to `SameSite=Lax` if SPA is same-site. |
| S-02 | **CORS `*` + `allow_credentials=True`.** Contradictory; forces someone to eventually set a permissive origin. | `server.py:2886-2891` | Remove the `"*"` default. Fail boot loudly if `CORS_ORIGINS` is unset. Explicit origin list only. |
| S-03 | **Stripe webhook swallows exceptions and returns 200.** Fee marked delivered by Stripe, never marked paid in DB. Silent money loss. | `server.py:557-598`, esp. `573-575` | Return 500 on handler failure so Stripe retries. Add a `stripe_events` collection keyed on `event.id` (unique index) for idempotency; insert-first, process, mark done. Reprocess job for stuck events. |
| S-04 | **Audit "signature" is `sha256(secret + msg)` with hardcoded public fallback `jobatlas-refund-v1`.** Length-extendable and, by default, forgeable by anyone. Verify endpoint never recomputes. **PARTIAL — F-11 (commit `4a85b96`)**: (a) fallback chain `REFUND_AUDIT_SIGN_SECRET → DRILL_SIGN_SECRET → "jobatlas-refund-v1"` collapsed to two independent required fields in `config.CryptoSettings`; the nested fallback was silently key-confusing any deployment that set `DRILL_SIGN_SECRET` but not `REFUND_AUDIT_SIGN_SECRET` (refund audits signed with the drill secret — different trust domain, no warning). (b) Same hardcoded fallback removed from `auth.py:664` (drill signature). **Still open**: `sha256(secret + msg)` is not HMAC (length-extension-attackable), and the verify endpoints do not recompute — they still look up the string in `refund_audit_receipts` / `drill_receipts` and return match/no-match, so a forged row that survives insertion validates on read. | `revisions.py:856-865`, `:972-981` | `hmac.new(secret, canonical, sha256)`. Fail boot if `REFUND_AUDIT_SIGN_SECRET` unset. Verify endpoint must **recompute** the HMAC over the stored rows and compare with `hmac.compare_digest`, not just look up the string. Same for the drill signature in `auth.py`. |
| ~~S-05~~ | ~~**Stripe key falls back to `sk_test_emergent`.**~~ **CLOSED — F-11 (commit `4a85b96`).** Fallback removed at `server.py:40`; `STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET` are both `Field(alias=...)` in `config.StripeSettings` with no default — a missing value fails boot with `Config error — required environment variables missing or invalid: Stripe: - STRIPE_SECRET_KEY`. | S-06 | **Plaintext third-party tokens in Mongo** (`crm_integrations.access_token`, `integration_tokens`). One DB read = full access to customers' HubSpot/Salesforce/Jira. | `auth.py:993-995`, work integrations | Envelope-encrypt at rest (AES-GCM with a KMS/`ENCRYPTION_KEY` DEK). Store `{ciphertext, nonce, key_id}`. Never return the token in any API response — only `last4`/`connected: true`. Add rotation + revoke endpoint. |
| S-07 | **No JWT revocation.** Logout only clears cookies; a stolen 12h token stays valid. No refresh rotation. | `deps.py:64-88`, `auth.py:198-201` | Add `token_version` int on `users`; embed in JWT; reject mismatch in `get_current_user`. | S-08 | **Captcha fails open.** `_verify_turnstile` returns `True` when `TURNSTILE_SECRET_KEY` is unset. Register/login are unthrottled. **PARTIAL — F-11 (commit `4a85b96`)**: `TURNSTILE_SECRET_KEY` is required-at-boot when `ENV=production` (enforced in `config.Settings._enforce_production_required`); in dev/test it stays optional. Add IP+email rate limiting (SlowAPI/Redis) on `/auth/login`, `/auth/register`, `/auth/resend-verification`, `/reference-check/{token}`. Constant-time login response to avoid user enumeration. |

| S-26 | **P0 CANDIDATE — dual cookie + Bearer auth with no first-party Bearer consumer.** `deps.py:72-74` accepts either the httpOnly `access_token` cookie or an `Authorization: Bearer <jwt>` header. `grep -rn "Authorization" frontend/src/` returns zero matches — no SPA code path sends a Bearer token. Add a test that hits every non-GET route with a Bearer + no cookie and asserts the CSRF middleware rejects it. |
